# PrismPanel 代理服与插件多平台设计

**文档状态**：已确认  
**适用阶段**：开发阶段，不提供旧插件仓库、旧插件协议和旧服务器配置迁移  
**更新日期**：2026-07-18

本文定义 PrismPanel 代理服务器、后端服务器自动同步、多平台 Prism 插件、插件平台分类、插件自动安装和部署目标记忆的完整实现方案。

---

## 一、目标与边界

### 1.1 目标

- 增加“代理服务器”创建入口，支持 Velocity 和 BungeeCord/Waterfall。
- 代理服复用普通固定实例的进程、控制台、文件、插件和生命周期管理能力。
- 普通服和镜像服可以选择需要同步到哪些代理服。
- 代理服可以通过树形选择器选择需要接入的后端服务器。
- 镜像服使用 “<server_id>_<slot>” 作为代理服务器名称，例如 “lobby_1”、“lobby_2”。
- 后端创建、删除、扩缩容、端口生效或代理插件重连时，自动同步完整后端列表。
- Prism 插件重构为 core、Spigot、Velocity 和 Bungee 四个模块。
- 插件仓库按平台分类，并支持自动安装和部署目标记忆。
- Velocity/Bungee Prism 插件负责动态后端注册和玩家跨服转移。

### 1.2 不做的功能

- 不迁移现有插件仓库、Manifest、数据库索引或当前单模块 PrismMC 协议。
- 不自动修改 Velocity 的 “try”。
- 不自动修改 BungeeCord 的 “priorities”。
- 不自动修改 forced-host、默认服务器或其他玩家入口路由。
- 不修改用户的 “velocity.toml” 或 “config.yml” 后端列表。
- 不保存或恢复被 Prism 动态覆盖的同名旧服务器地址。
- 不因上传插件新版本而自动部署到现有服务器。
- 不为不同节点上的重名后端自动添加节点前缀。

---

## 二、已确定决策

1. 前端展示普通服务器、镜像服务器和代理服务器三种创建类型。
2. 内部部署形态仍为 “standalone” 或 “mirror”；代理服使用 “standalone”，平台使用 “velocity” 或 “bungee”。
3. 普通服和镜像服的平台使用 “paper” 或 “spigot”，插件分类统一为 “spigot”。
4. 代理后端通过 Prism Velocity/Bungee 插件动态注册。
5. 后端地址使用 Panel 保存的 daemon 连接 URL 主机部分。
6. 停止的后端只要仍被选择，就继续保留在代理列表中。
7. 删除服务器、取消同步或减少镜像实例数量时移除对应后端。
8. 同名手工服务器允许被直接覆盖，取消同步时也不恢复旧地址。
9. 子服部署成功但代理同步失败时不回滚部署，允许单独重试。
10. 节点级勾选是持续规则，未来新增的兼容服务器默认被选中。
11. 单个服务器可以显式覆盖节点默认选择。
12. 插件自动安装只作用于以后新建的兼容服务器。
13. 自动安装失败不回滚服务器创建，但阻止自动启动；用户确认后仍可手动启动。
14. 同一个代理中不允许出现两个相同的最终实例 ID。
15. Bungee 分类覆盖 BungeeCord 和 Waterfall；Velocity 第一版支持 Velocity 3.x。

## 三、服务器模型

### 3.1 部署形态与平台分离

“type” 表示文件和实例如何派生，“platform” 表示服务器软件平台。

| 前端类型 | type | platform | 插件分类 |
|---|---|---|---|
| 普通服务器 | standalone | paper / spigot | spigot |
| 镜像服务器 | mirror | paper / spigot | spigot |
| Velocity 代理服 | standalone | velocity | velocity |
| Bungee 代理服 | standalone | bungee | bungee |

代理服不增加独立生命周期实现，是否具备代理能力由 “platform” 判断。

### 3.2 配置格式

开发阶段直接升级服务器配置 Schema，不提供旧配置迁移。

普通 Paper 服务器示例：

~~~json
{
  "schema_version": 2,
  "type": "standalone",
  "platform": "paper",
  "server_id": "survival",
  "name": "生存服",
  "workspace": "/srv/minecraft/survival",
  "port": 25565,
  "process": {
    "start_command": "java -jar paper.jar nogui",
    "stop_command": "stop",
    "stop_timeout_seconds": 60,
    "auto_start": false,
    "auto_restart": true
  },
  "console": {"encoding": "utf-8"}
}
~~~

Velocity 代理服示例：

~~~json
{
  "schema_version": 2,
  "type": "standalone",
  "platform": "velocity",
  "server_id": "proxy-main",
  "name": "主代理",
  "workspace": "/srv/minecraft/proxy-main",
  "port": 25577,
  "process": {
    "start_command": "java -jar velocity.jar",
    "stop_command": "end",
    "stop_timeout_seconds": 60,
    "auto_start": true,
    "auto_restart": true
  },
  "console": {"encoding": "utf-8"}
}
~~~

### 3.3 校验规则

- “mirror” 只允许 “paper” 或 “spigot”。
- “velocity” 和 “bungee” 只允许 “standalone”。
- 代理服只有一个实例，实例 ID 等于 “server_id”。
- 镜像实例 ID 固定为 “<server_id>_<slot>”。
- 所有平台继续参与 daemon 内的端口冲突校验。
- 代理服的 “port” 是声明监听端口，第一版不自动修改代理原生配置。
- 用户必须保证代理实际监听端口与 Panel 配置一致。
- 代理服不允许作为另一个代理服的后端。

### 3.4 后端实例名称

- 普通固定实例的代理名称等于 “server_id”。
- 镜像实例的代理名称等于实际 “instance_id”。
- 显示名称不参与代理定位，修改显示名称不会改变代理服务器名称。
- 同一代理选中的全部后端实例名称必须唯一。
- 不同节点出现同名实例时，树形选择器标记冲突并禁止保存。

### 3.5 有效后端端口

- 实例运行且存在 “runtime_port” 时使用运行端口。
- 实例停止时使用 “configured_port”。
- 运行中修改配置端口但尚未重启时，继续同步旧运行端口。
- 实例下次成功启动后，再同步新的配置端口。
- 地址主机从后端节点 daemon 连接 URL 提取。
- IPv6 地址通过标准 “[address]:port” 格式输出。

## 四、Prism 插件多模块架构

### 4.1 工程结构

插件工程改为 Gradle Kotlin DSL 多模块项目：

~~~text
prism-plugin/
├── settings.gradle.kts
├── build.gradle.kts
├── gradle.properties
├── core/
│   └── src/main/java/com/xigua/prism/core/
├── spigot/
│   └── src/main/
│       ├── java/com/xigua/prism/spigot/
│       └── resources/plugin.yml
├── velocity/
│   └── src/main/
│       ├── java/com/xigua/prism/velocity/
│       └── resources/velocity-plugin.json
└── bungee/
    └── src/main/
        ├── java/com/xigua/prism/bungee/
        └── resources/bungee.yml
~~~

借鉴 Floodgate 的模块边界和平台成品 JAR 方式，但不引入 Guice、注解处理器、自动绑定和公共 API 模块。各平台入口显式构造 core 服务。

### 4.2 core 模块职责

- 读取 daemon 注入的环境变量。
- 校验 daemon WebSocket 必须是本机回环地址。
- 插件认证、心跳、断线重连和关闭。
- 双向请求协议、“request_id”、超时、错误码和响应关联。
- 有界发送队列，避免连接阻塞导致内存无限增长。
- JVM 堆内存、线程数等公共指标。
- 平台能力声明。
- 后端目录快照和玩家转移请求模型。
- 日志、调度、遥测和代理控制的小型接口。

core 不依赖 Bukkit、Velocity、Bungee 或其传递依赖。

### 4.3 平台接口

按职责拆分：

~~~text
PrismLogger
PlatformScheduler
TelemetryProvider
PluginInventoryProvider
ProxyBackendRegistry
PlayerTransferService
~~~

- Spigot 实现遥测、玩家和插件列表，不实现代理接口。
- Velocity/Bungee 实现代理后端注册和玩家转移。
- 平台 API 操作必须经对应平台调度器执行。
- WebSocket 回调线程不得直接调用 Bukkit、Velocity 或 Bungee API。

### 4.4 平台模块职责

“spigot”：

- Bukkit/Paper 插件生命周期。
- TPS、MSPT、在线玩家、延迟和加入时间。
- Bukkit/Paper 插件列表和文件摘要。
- 后续玩家白名单、OP、踢出和消息能力。

“velocity”：

- Velocity 3.x 插件生命周期。
- 在线玩家及当前后端服务器上报。
- 已加载 Velocity 插件列表。
- 动态注册、更新和注销后端。
- 按玩家 UUID 发起服务器连接。

“bungee”：

- BungeeCord/Waterfall 插件生命周期。
- 在线玩家及当前后端服务器上报。
- 已加载 Bungee 插件列表。
- 动态注册、更新和注销后端。
- 按玩家 UUID 发起服务器连接。

### 4.5 构建产物

每个平台模块将 core 和 Gson 打入独立成品 JAR，平台 API 使用 “compileOnly”：

~~~text
Prism-Spigot.jar
Prism-Velocity.jar
Prism-Bungee.jar
~~~

Gson 等随 JAR 打包的依赖重定位到 Prism 自有命名空间，避免与服务器平台或其他插件冲突。

## 五、插件 WebSocket 协议

### 5.1 协议升级

当前仅支持插件向 daemon 上报。新协议改为双向请求模型，不兼容旧 PrismMC 插件。

认证消息增加：

~~~json
{
  "type": "auth",
  "token": "...",
  "instance_id": "proxy-main",
  "session_id": "...",
  "pid": 1234,
  "platform": "velocity",
  "capabilities": [
    "telemetry",
    "plugin.inventory",
    "proxy.backends",
    "player.transfer"
  ]
}
~~~

### 5.2 daemon 下发命令

~~~json
{
  "type": "proxy.backends.replace",
  "request_id": "req-01",
  "data": {
    "revision": 12,
    "servers": [
      {"id": "lobby_1", "address": "192.168.1.20:25565"},
      {"id": "lobby_2", "address": "192.168.1.20:25566"}
    ]
  }
}
~~~

统一响应：

~~~json
{
  "type": "response",
  "request_id": "req-01",
  "success": true,
  "data": {
    "revision": 12,
    "applied": 2,
    "removed": 0
  }
}
~~~

玩家转移命令：

~~~json
{
  "type": "player.transfer",
  "request_id": "req-02",
  "data": {
    "player_uuid": "00000000-0000-0000-0000-000000000000",
    "target_server_id": "lobby_1"
  }
}
~~~

### 5.3 并发与可靠性

- daemon 为每个插件连接维护有界发送队列和待响应请求表。
- 相同 “request_id” 只能完成一次。
- 请求具有固定超时，断线立即失败所有等待请求。
- 插件平台操作完成后才返回成功。
- 后端快照携带单调递增 “revision”。
- 相同修订和内容重复下发时返回成功但不重复操作。
- 旧修订默认拒绝，避免乱序覆盖。
- 插件重连后 daemon 立即下发本地缓存的最新快照。

## 六、插件仓库平台分类

### 6.1 目录结构

不迁移旧仓库，直接启用新目录：

~~~text
plugins/
├── spigot/<plugin_id>/<artifact_id>/
├── velocity/<plugin_id>/<artifact_id>/
└── bungee/<plugin_id>/<artifact_id>/
~~~

插件类型必须写入仓库索引、版本 Manifest、MySQL 索引和 daemon 部署包，不能只作为前端标签。

### 6.2 描述文件

| plugin_type | 描述文件 | 唯一身份 |
|---|---|---|
| spigot | plugin.yml / paper-plugin.yml | name，不区分大小写 |
| velocity | velocity-plugin.json | id，不区分大小写 |
| bungee | bungee.yml | name，不区分大小写 |

- 上传时必须显式选择 “plugin_type”。
- 选择类型与 JAR 内描述文件不匹配时拒绝上传。
- 同类型、同身份的新 JAR 作为同一插件的新版本。
- 不同类型允许存在同名插件。
- 一个制品只能属于一个插件类型。
- Velocity 的显示名称和稳定 ID 分开保存。

### 6.3 仓库元数据

插件级索引增加：

~~~yaml
schema_version: 2
plugin_type: spigot
plugin_id: luckperms
name: LuckPerms
auto_install: true
current_artifact_id: 5
next_artifact_id: 6
~~~

版本 Manifest 增加：

~~~yaml
schema_version: 2
plugin_type: spigot
artifact_id: 5
plugin_id: luckperms
name: LuckPerms
version: 5.4.0
descriptor_identity: LuckPerms
~~~

“auto_install” 属于插件，不属于版本。上传新版本默认继承现有值，上传页面可以显式修改。

### 6.4 daemon 分流

- 部署仓库制品时，bundle 必须包含 “plugin_type”。
- daemon 根据目标服务器 “platform” 检查类型兼容性。
- 普通服和镜像服只接受 “spigot”。
- Velocity 代理服只接受 “velocity”。
- BungeeCord/Waterfall 代理服只接受 “bungee”。
- 从服务器插件页直接上传 JAR 时，不再询问类型，由目标平台确定解析器。
- 同名替换只在同平台描述符身份相同时成立。
- 错误平台的 JAR 返回稳定的 “PLUGIN_PLATFORM_MISMATCH”。
- 扫描 plugins 目录时按目标平台解析；无法识别或平台不匹配的 JAR作为告警项展示，不参与同名替换。

## 七、插件自动安装

### 7.1 适用范围

- 只安装到以后新建的兼容服务器组。
- 不追溯安装到已有服务器。
- 上传新版本不会触发现有服务器自动升级。
- 创建普通服、镜像服和代理服时均执行。
- Prism 自身三个平台插件不做特殊硬编码，也通过仓库 “auto_install” 实现。

### 7.2 创建顺序

1. 校验服务器配置、平台、目录和端口。
2. 在 daemon 创建服务器配置，并标记初始化中。
3. 导入用户选择的初始化 ZIP。
4. Panel 查询该插件类型全部 “auto_install=true” 的当前版本。
5. 按稳定顺序部署到目标。
6. 镜像服将插件安装到镜像目录。
7. 镜像服执行首次镜像部署。
8. 保存代理同步选择关系。
9. 标记服务器初始化完成。
10. 自动安装全部成功时，按 “auto_start” 决定是否启动。

### 7.3 安装目标

- 普通服：工作目录下的 plugins 目录。
- Velocity/Bungee：代理工作目录下的 plugins 目录。
- 镜像服：镜像源的 plugins 目录，派生实例通过镜像部署获得插件。
- 镜像实例数量增加时继续从现有镜像源获得自动安装插件。

### 7.4 失败语义

自动安装某个插件失败时：

- 服务器配置和成功导入的文件不回滚。
- 其他自动安装插件继续处理。
- 返回逐插件成功与失败结果。
- 服务器标记为 “initialization_incomplete”。
- daemon 自动启动流程跳过该服务器。
- 用户手动启动时显示失败项和风险确认，确认后允许启动。
- 自动安装重试全部成功后清除初始化不完整状态。

## 八、插件部署目标记忆

### 8.1 基本语义

每个插件按 “plugin_type + plugin_id” 保存一份部署选择，与具体版本无关。

例如 1.0.4 选择部署到 lobby、不部署到 test，上传 1.0.5 后再次打开部署窗口时仍恢复该选择。上传新版本本身不执行部署。

### 8.2 目标范围

- spigot 插件只展示普通服和镜像服。
- velocity 插件只展示 Velocity 代理服。
- bungee 插件只展示 BungeeCord/Waterfall 代理服。
- 镜像服务器组是一个部署目标，不单独选择 lobby_1 或 lobby_2。
- 节点复选框只影响该节点内类型兼容的服务器。

### 8.3 持续节点规则

- 勾选节点表示当前及未来新增的兼容服务器默认选中。
- 单个服务器可显式取消，形成排除项。
- 未勾选节点时可单独勾选服务器，形成包含项。
- 每次打开部署窗口都根据当前服务器目录重新计算树。
- 用户提交部署时保存当前范围，作为下一次默认值。
- 新增服务器是否自动安装仍只由 “auto_install” 决定；部署目标记忆不会自动触发部署。

## 九、代理与后端关系

### 9.1 唯一数据源

代理与后端的多对多关系保存在 Panel 数据库，不分别写入代理 daemon 和后端 daemon 的服务器 JSON。

代理配置页面和子服配置页面只是同一关系的两种编辑入口：

- 创建或编辑代理服：选择需要接入的后端服务器。
- 创建或编辑普通服/镜像服：选择需要同步到的代理服。

任何入口保存后都更新同一套规则并触发相关代理重新同步。

### 9.2 节点默认值与服务器覆盖值

树形选择采用两级规则：

~~~text
节点 A：默认同步
├── lobby：继承节点设置
├── survival：明确不同步
└── 未来新建服务器：默认同步

节点 B：默认不同步
├── test：明确同步
└── 未来新建服务器：默认不同步
~~~

有效选择算法：

1. 存在服务器级覆盖值时使用覆盖值。
2. 否则存在节点级默认值时使用节点默认值。
3. 否则默认为不选择。

树组件使用三态复选框：

- 全选：节点默认选中且无排除，或当前全部子项有效选中。
- 未选：节点默认未选且无包含，或当前全部子项有效未选。
- 半选：存在显式包含、显式排除或当前子项状态混合。

### 9.3 创建服务器时的代理选择

- 创建页面展示按节点分组的代理服树。
- 某代理已设置目标节点默认同步时，新服务器默认勾选该代理。
- 用户取消默认勾选时，为新服务器保存明确排除。
- 用户额外勾选其他代理时，为新服务器保存明确包含。
- 未修改的继承项不写冗余覆盖记录。

### 9.4 创建代理时的后端选择

- 创建页面展示按节点分组的普通服和镜像服。
- 节点勾选保存持续的节点默认规则。
- 镜像服以服务器组为选择单位。
- 代理服不出现在后端树中。
- 冲突实例 ID 在保存前集中校验。

### 9.5 镜像组展开

绑定对象是镜像服务器组，不是单个派生实例。

~~~text
选择 lobby
→ lobby_1
→ lobby_2
→ lobby_3
~~~

- “instance_count” 增加时自动加入新实例。
- “instance_count” 减少时移除范围外实例。
- 范围外旧目录和旧进程即使仍存在，也不再同步到代理。
- 镜像实例停止时仍保留代理条目。

### 9.6 数据表建议

服务器目录使用 Panel 计划中的 “server_groups” 和 “instances” 表，保存 daemon 最近上报的配置与有效端口。

代理同步规则：

~~~text
proxy_sync_rules
├── proxy_node_id
├── proxy_server_id
├── scope_type          node | server
├── backend_node_id
├── backend_server_id   节点规则时为空
├── selected
├── created_at
└── updated_at
~~~

唯一约束：

~~~text
proxy_node_id
proxy_server_id
scope_type
backend_node_id
backend_server_id
~~~

插件部署偏好使用独立表，但复用相同的范围解析器：

~~~text
plugin_deploy_preferences
├── plugin_type
├── plugin_id
├── scope_type
├── node_id
├── server_id
├── selected
├── created_at
└── updated_at
~~~

### 9.7 离线节点

- Panel 持久化最后已知服务器组和实例端口。
- 后端节点临时离线时不从代理目录删除。
- 已同步代理继续使用上一次成功地址。
- 节点从未成功上报端口时，关系显示为等待同步。
- 节点恢复后重新计算有效端口并触发同步。
- 明确删除节点时，相关关系和代理条目一并移除。

## 十、代理后端同步

### 10.1 编排位置

同步由 Panel 统一编排，原因是代理和后端可能位于不同节点。后端 daemon 不直接连接或修改其他节点上的代理服。

~~~text
后端拓扑变化
→ daemon 上报服务器与实例状态
→ Panel 更新服务器目录
→ Panel 解析代理同步规则
→ Panel 为每个相关代理生成完整快照
→ Panel 调用代理所在 daemon
→ daemon 缓存并下发给代理插件
→ 插件动态应用
→ 结果返回 Panel
~~~

### 10.2 同步触发条件

- 创建普通服务器或镜像服务器。
- 删除普通服务器或镜像服务器。
- 修改代理同步选择。
- 修改镜像实例数量。
- 镜像部署完成。
- 实例成功启动后有效运行端口发生变化。
- 后端节点 daemon 连接地址发生变化。
- 后端节点从离线恢复。
- 代理插件首次连接或重新连接。
- 代理实例重新启动。
- 用户点击“重新同步”。

停止实例不触发删除。

### 10.3 完整快照

每次向代理发送完整期望列表，而不是只发送增删命令：

~~~json
{
  "proxy_instance_id": "proxy-main",
  "revision": 12,
  "servers": [
    {
      "id": "lobby_1",
      "node_id": "node-a",
      "server_id": "lobby",
      "address": "192.168.1.20:25565"
    }
  ]
}
~~~

完整快照具备以下优点：

- 重试幂等。
- 自然处理删除与镜像缩容。
- 插件重连后可以恢复完整状态。
- 不依赖历史增量是否全部送达。
- 可以通过内容哈希跳过无变化同步。

### 10.4 daemon 本地缓存

代理 daemon 原子保存最近一次期望快照：

~~~text
data/runtime/proxies/<proxy_instance_id>/backends.json
~~~

- Panel 断线不清空缓存。
- daemon 重启后继续读取缓存。
- 代理插件认证成功后立即收到缓存快照。
- Panel 后续连接时以更高修订覆盖缓存。
- 缓存只保存 Prism 期望后端，不保存代理原始手工地址。

### 10.5 动态应用

Velocity：

- 使用 ProxyServer 动态注册 RegisteredServer。
- 地址变化时注销当前同名对象并注册新对象。
- 删除快照中不存在的 Prism 管理名称。

BungeeCord/Waterfall：

- 使用平台 API 构造 ServerInfo。
- 将同名条目直接替换为 Prism 地址。
- 删除快照中不存在的 Prism 管理名称。

应用前先校验全部名称、地址和重复项。平台不支持真正的批量原子修改，因此插件保存上一个 Prism 快照；发生中途失败时只回滚到上一个 Prism 快照，不恢复被覆盖的手工地址。

### 10.6 同名覆盖

- Prism 不读取、保存或恢复同名旧服务器地址。
- 同名动态服务器直接由 Prism 新地址替换。
- 绑定存在期间，每次代理重启后都会重新覆盖。
- 取消绑定时直接注销 Prism 当前条目，不恢复覆盖前对象。
- 原生配置文件保持不变；若代理未来脱离 Prism 管理并重启，平台自行加载原生配置不属于 Prism 恢复行为。

### 10.7 冲突处理

同一代理最终列表中出现重复实例 ID 时：

- 不发送部分列表。
- 返回 “PROXY_SERVER_ID_CONFLICT”。
- 错误包含冲突名称和涉及节点。
- 前端在树中标记冲突项。
- 用户必须取消其中一个选择或修改服务器 ID。

### 10.8 同步失败

- 子服创建、修改或镜像部署结果不回滚。
- 代理同步状态标记为失败。
- 保存失败代理、错误码、错误信息和目标修订。
- 其他代理继续同步。
- 提供单代理和全部失败代理重试。
- 新快照生成后，旧失败任务不再重试旧修订。
- 代理插件未安装或未连接时返回 “PROXY_PLUGIN_UNAVAILABLE”。

### 10.9 同步状态

每个代理保存：

~~~text
desired_revision
applied_revision
desired_hash
applied_hash
status
last_attempt_at
last_success_at
last_error_code
last_error
~~~

状态至少包括：

~~~text
pending
syncing
synced
failed
plugin_offline
conflict
~~~

## 十一、玩家转移

### 11.1 玩家上报

Velocity/Bungee 插件上报：

- 玩家 UUID 和名称。
- 当前代理实例 ID。
- 当前后端服务器 ID。
- 延迟和连接时间。

Panel 根据代理插件上报确定玩家当前由哪个代理管理。

### 11.2 转移流程

1. 前端选择玩家和目标服务器。
2. Panel 校验 “player.transfer” 权限。
3. Panel 校验目标服务器在该代理当前目录中。
4. Panel 向代理所在 daemon 发送请求。
5. daemon 转发给当前代理插件。
6. 插件再次确认玩家仍在线、目标仍注册。
7. 平台 API 发起连接。
8. 插件返回明确成功或失败。
9. Panel 写入审计日志。

目标镜像实例使用实际实例 ID，例如 “lobby_2”。

## 十七、验收标准

1. 前端可以创建 Velocity 和 BungeeCord/Waterfall 代理服。
2. 代理服复用普通服的进程、控制台、文件和插件管理。
3. 普通服、镜像服和代理服均具有明确 “platform”。
4. 插件仓库可以上传并校验 Spigot、Velocity 和 Bungee 插件。
5. 同名不同平台插件可以独立保存版本。
6. 标记自动安装的插件只安装到以后新建的兼容服务器。
7. 自动安装失败不回滚创建，但阻止自动启动并展示失败项。
8. 插件部署窗口记住上一次树形选择，新版本继续使用该偏好。
9. 节点级选择会影响未来新增的兼容服务器。
10. 代理配置和子服配置修改的是同一关系数据。
11. 镜像组选择自动展开为 “server_id_N” 实例。
12. 停止后端仍在代理列表，删除或缩容后移除。
13. 后端地址使用 daemon 连接 URL 主机和实例有效端口。
14. 代理插件动态覆盖同名服务器且不保存、恢复旧地址。
15. 多节点重名实例不能同时同步到同一代理。
16. 子服部署成功、代理同步失败时可单独重试，不回滚部署。
17. Velocity/Bungee 插件可以执行玩家跨服转移并返回明确结果。
18. 系统从不自动修改 “try”、“priorities”、forced-host 或默认路由。
19. 所有同步、自动安装、插件部署和玩家转移均经过权限校验并写入审计。

## 十八、实现原则

- 服务器生命周期保持单一实现，代理能力通过平台扩展。
- core 只依赖平台抽象，平台模块不复制连接协议。
- 代理关系和插件部署偏好分别保存，但复用同一范围解析器和树形组件。
- Panel 保存跨节点关系和期望状态，daemon 保存节点本地执行状态。
- 同步使用完整快照和修订号，不依赖脆弱的增量历史。
- 自动安装、代理同步和玩家转移均返回结构化目标结果。
- 第一版只实现已确认能力，不预留自动路由、跨网络调度或插件公共 API。

## 一、项目定位

### 1.1 项目目标

**PrismPanel** 是面向 Minecraft 多实例、多 Linux 节点场景的分布式管理面板。项目最终覆盖实例部署、进程启停、控制台、监控、插件和资源包管理；当前首先解决“节点可靠管理 Minecraft 进程”这一基础问题。

### 1.2 目标用户

| 用户类型 | 参考规模 | 核心需求 |
|---|---:|---|
| 小型服主 | 1-3 台节点，5-10 个实例 | 稳定启停、控制台、基础监控 |
| 中型运营团队 | 5-10 台节点，20-50 个实例 | 多节点管理、批量部署、可审计 |
| 插件/模组开发者 | 单机或小型测试集群 | 快速创建、替换和重启测试实例 |

### 1.3 核心原则

- **控制面与执行面分离**：面板负责用户、权限、期望状态和任务编排；守护进程负责节点本地的进程与文件操作。
- **节点主动连接**：守护进程主动向面板建立 TLS/gRPC 长连接，节点不对公网开放管理端口。
- **期望状态与实际状态分离**：面板保存期望配置，守护进程报告本地实际状态，通过配置修订号对账。
- **失败可见、操作有界**：远程操作必须有请求 ID、超时、状态变更和明确错误码；不允许无限等待、无限缓冲和无限重启。
- **默认最小权限**：守护进程使用独立非 root 用户，实例只能访问自己的工作目录。
- **先完成闭环，再扩展功能**：v0.1 不引入 Docker、插件热加载、全量文件管理等非必要能力。

## 二、系统架构

### 2.1 总体结构

```text
┌─────────────────────────────────────────────┐
│ Web 浏览器              Windows 桌面应用     │
│ Vue 3                    Wails + Vue 3      │
└──────────────────────┬──────────────────────┘
                       │ HTTPS/WSS
┌──────────────────────▼──────────────────────┐
│                面板后端                     │
│ 身份权限 · 节点注册 · 期望状态 · 指令路由 · 审计 │
└───────────────▲───────────▲─────────────────┘
                │           │
       节点主动建立 TLS/gRPC 双向流
                │           │
        ┌───────┴──┐   ┌────┴─────┐
        │ 守护进程 A │   │ 守护进程 B │
        │ 实例与资源 │   │ 实例与资源 │
        └───┬───┬───┘   └───┬───┬───┘
            │   │           │   │
           MC1 MC2          MC3 MC4
```

浏览器不直接连接守护进程。用户认证、授权、审计和 WebSocket 会话均由面板后端统一处理。

### 2.2 组件职责

| 组件 | 负责 | 不负责 |
|---|---|---|
| 前端 | 用户交互、状态和控制台展示 | 直接访问节点、保存节点密钥 |
| 面板后端 | 用户权限、节点注册、期望配置、指令路由、审计 | 直接管理 Linux 子进程 |
| 守护进程 | 本地实例、进程树、标准输入输出、资源采集、配置缓存 | 用户系统、跨节点调度、前端会话 |
| 子服插件 | TPS、玩家、插件状态等游戏内部数据 | 操作系统进程与节点文件 |

### 2.3 技术基线

| 层级 | 技术选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite + Element Plus | Web 与 WinApp 共用 UI |
| 桌面端 | Wails | 仅作桌面容器与本地系统适配 |
| 面板后端 | Go | REST API、WebSocket、gRPC 服务端 |
| 守护进程 | Go | Linux 优先，单一可执行文件 |
| 节点协议 | Protocol Buffers + gRPC | 控制流与控制台流分离 |
| 面板数据 | MySQL | 用户、节点、实例期望配置和审计数据 |
| 节点本地数据 | 原子替换的 JSON 文件 | v0.1 数据量小，暂不引入 SQLite |
| 子服插件 | Java（Paper/Spigot） | v0.1 不实现，后续提供游戏内数据 |

Redis、消息队列和独立时序数据库不是 v0.1 的前置依赖。仅在多面板实例、跨进程任务或长期指标存储成为已验证需求时引入。

## 三、项目基本框架

### 3.1 Go 模块决策

当前 `panel/go.mod` 和 `daemon/go.mod` 只是空骨架。正式开发前建议改为**仓库根目录单 Go Module，两个独立命令入口**：

- 面板与守护进程仍然能够独立编译、发布；
- Proto 生成代码只有一份，不需要 `replace` 或第三个共享模块；
- 早期项目不承担多模块版本管理的额外复杂度。

Go Module 路径应在远程仓库地址确定后一次性设置，不继续使用 `PrismPanel` 这类临时 Module 名。

### 3.2 建议目录

```text
PrismPanel/
├── go.mod                         # 单一 Go Module
├── cmd/
│   ├── prism-panel/               # 面板后端入口
│   └── prism-daemon/              # 守护进程入口
├── internal/
│   ├── panel/                     # 面板专属业务
│   └── daemon/                    # 守护进程专属业务
├── api/proto/prism/v1/           # 原始 .proto 文件
├── gen/go/prism/v1/              # 生成的 Go 协议代码
├── frontend/                      # Vue 3 Web 前端
├── winapp/                       # Wails 桌面容器
├── prism-plugin/                 # Minecraft 服务端插件
├── deploy/
│   ├── systemd/                  # Linux 服务单元
│   └── docker/                   # 面板部署，非 v0.1 节点运行时
├── scripts/                       # 协议生成、构建和发布
└── docs/                         # 架构、ADR、API 和部署文档
```

不预设 `internal/shared` 通用代码桶。仅当面板和守护进程出现稳定、真实的重复时，再提取共享包。

### 3.3 依赖方向

```text
cmd -> 应用组装 -> 领域逻辑 -> 进程/存储/网络适配
                         -> 生成的协议类型
```

- 领域层不依赖 gRPC Server、具体文件格式或 Linux 系统调用。
- 协议层只负责 DTO 转换和传输，不直接操作进程。
- 只对进程、时钟、存储和网络等外部边界建立窄接口，不为每个结构体预制接口。

## 四、v0.1 守护进程范围

### 4.1 必须完成

| 能力 | 交付范围 |
|---|---|
| 启动与配置 | 配置读取、目录初始化、单实例锁、信号处理、结构化日志 |
| 节点身份 | 一次性注册令牌、节点独立凭据、撤销与重新注册 |
| 通信 | 主动 TLS/gRPC 双向流、自动重连、心跳、协议版本校验 |
| 实例注册表 | 加载和缓存实例配置、修订号对账、拒绝重复 ID |
| 进程生命周期 | 启动、优雅停止、重启、强制终止、意外退出处理 |
| 状态机 | `STOPPED/STARTING/RUNNING/STOPPING/FAILED` 及合法转换 |
| 控制台 | stdout/stderr、环形缓冲、按需订阅、stdin 命令 |
| 监控 | 节点 CPU/内存/磁盘/负载和实例 CPU/RSS/运行时长 |
| 容错 | 退避重连、操作去重、崩溃重启限流、守护进程有界退出 |
| Linux 部署 | 非 root 运行、systemd 单元、数据与凭据权限 |

### 4.2 明确不做

- Docker/容器实例、PTY 和通用游戏进程。
- Web 文件管理、压缩解压、URL 下载和大文件上传。
- 插件、Mod、资源包、镜像、备份和端口池。
- TPS、玩家列表和游戏内就绪状态；这些数据需要 Minecraft 插件或专用查询协议。
- 守护进程升级后无感接管已运行 Java 进程。v0.1 中守护进程与实例生命周期绑定。
- 多面板高可用、跨地域消息队列和长期监控数据存储。

### 4.3 关键设计摘要

- 每个实例由串行的 `InstanceSupervisor` 管理，同一实例的启停操作不并发执行。
- v0.1 仅构造受约束的 Minecraft Java 启动参数，不接受任意 Shell 命令。
- Linux 下为实例建立独立进程组，终止面向整个进程组，避免残留子进程。
- 正常停止先向 stdin 写入 `stop`，超时后依次使用 `SIGTERM` 和 `SIGKILL`。
- 进程成功创建只表示 `RUNNING`，不等于 Minecraft 已完全就绪。
- 控制指令与控制台数据使用独立 gRPC 流，避免日志洪峰阻塞心跳和停服指令。
- 控制台采用有界缓冲；消费者过慢时丢弃旧输出，并明确报告日志序列缺口。
- 面板是期望配置权威源，守护进程按修订号缓存；本地孤儿实例不会被自动删除。

## 六、v0.1 交付门槛

1. 同一实例的并发启停、重启指令不会创建重复进程或卡死状态机。
2. 正常停止、停止超时和强制终止均能结束整个实例进程组。
3. 面板断开不影响已运行实例；重连后自动上报完整实际状态。
4. 高频控制台输出不会导致内存无界增长，不阻塞心跳或停服指令。
5. 节点凭据独立、可撤销，日志不输出明文密钥。
6. 工作目录无法通过 `..`、绝对路径或符号链接逃逸配置的实例根目录。
7. 通过单元测试、进程集成测试、gRPC 重连测试和 `go test -race`。
8. 能以非 root systemd 服务运行，并完成有界优雅退出。

## 七、已确定的架构决策

| 主题 | 当前决策 | 说明 |
|---|---|---|
| 节点连接方向 | 守护进程主动连接面板 | 适配 NAT 和防火墙，减少节点暴露面 |
| 节点协议 | gRPC 双向流 | 类型明确，支持心跳、指令和事件 |
| 控制流与日志流 | 分离 | 防止高流量日志影响控制面 |
| 节点身份 | TLS + 每节点独立令牌 | v0.1 支持撤销/重置，mTLS 自动签发延后 |
| 实例恢复 | 守护进程与子进程生命周期绑定 | v0.1 不承诺重启后重新接管 stdin/stdout |
| 本地存储 | 原子 JSON 文件 | 暂不需要本地关系数据库 |
| 进程启动 | 受约束参数且不经 Shell | 减少注入和转义差异 |
| Docker | v0.1 延后 | 先验证进程监督核心模型 |
| TPS | v0.1 延后 | 操作系统进程指标不能替代游戏 TPS |

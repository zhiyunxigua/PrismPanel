# 网络白名单实现设计

**状态：已实现（待 Linux 实机验证）**
**范围：Linux 原生 nftables，公网端口暴露巡检不在本阶段实现。**

## 1. 目标与边界

本功能管理节点入站端口的来源白名单。第一版只支持运行 Prism daemon 的 Linux 节点，使用 nftables；Windows 节点返回“不支持”，不调用 Windows Firewall；不兼容宝塔、UFW、firewalld 等第三方防火墙控制面。

这里的 `table inet prismpanel` 是 Linux 内核 nftables 的独立规则表，不是 MySQL 表。Prism 只创建、读取和删除这一张专用表，不修改其他工具或管理员创建的规则。

公网端口暴露巡检、宝塔适配、端口转发和多防火墙后端属于后续阶段。

## 2. 权威状态

daemon 是规则的唯一权威：

- daemon 在本地原子 JSON 文件中保存逻辑规则、修订号、系统访问设置和最近成功应用的指纹。
- daemon 根据本地状态生成 nftables 规则，并在启动、状态查询和写入前读取实际 `table inet prismpanel`。
- Panel 不保存权威规则副本；它只校验用户权限、转发命令、展示 daemon 返回的状态并写入操作审计。
- Panel 离线时只能展示最后读取结果，不能把缓存描述为实时防火墙状态。

所有写操作携带 `expected_revision`。daemon 按节点串行处理，修订号不一致时返回冲突，客户端必须重新读取后再提交，避免多个面板或多个管理员相互覆盖。

## 3. 规则模型

业务规则包含：

- 规则 ID、启用状态、备注、创建和更新时间。
- 协议：`tcp`、`udp` 或二者。
- 一个或多个端口区间，端口范围为 `1-65535`。
- 一个或多个 IPv4/IPv6 地址或 CIDR。

daemon 将单 IP 规范化为 `/32` 或 `/128`，CIDR 使用掩码后的标准形式。输入不接受 nftables 文本、主机名、端口名或任意 Shell 参数。

启用的业务规则不得在同一 `(协议, 端口)` 上重叠；需要允许多个来源时，应在同一规则中添加多个 CIDR。daemon 监听端口不能被业务规则接管，包含该端口的区间会被拒绝。

## 4. nftables 结构

规则表使用 `inet` 地址族，同时处理 IPv4 和 IPv6。概念结构如下：

```text
table inet prismpanel
├── set prismpanel_control4/6        长期保留的 Panel 控制来源
├── set prismpanel_direct_grants4/6  带 timeout 的浏览器临时来源
└── chain input
    ├── loopback 放行
    ├── 系统访问链：已建立连接、Panel 控制来源、临时浏览器 grant
    ├── daemon 端口的最终拒绝（仅系统访问保护启用时）
    ├── 业务规则的来源放行
    └── 已接管业务端口的最终拒绝
```

系统访问链位于业务规则之前，仅作用于 daemon 监听端口。普通白名单页面不能编辑或删除系统规则，也不能通过业务规则绕过系统端口保护。该链只保证 Prism 自己表内的规则优先级；其他防火墙控制面仍可能额外拒绝流量，因此不在本阶段混用多个可写后端。

永久业务规则或系统设置变更：daemon 生成完整候选规则，先执行 `nft --check --file -`，再使用单次 `nft --file -` 原子替换专用表。临时 grant 只更新专用 timeout set，不重建业务规则表。

## 5. 直接访问授权

daemon 与浏览器当前共用监听端口，因此临时授权不是按 HTTP 路径生效，而是按来源 IP 和 daemon 端口生效。应用层 ticket 仍负责资源、方法、实例和文件路径授权。

浏览器直接打开控制台或文件操作时：

1. Panel 校验当前用户的资源权限。
2. Panel 从可信连接来源取得用户 IP，并在现有 `ticket.create` 请求中携带来源 IP 和会话标识。
3. daemon 签发来源 IP 绑定的短期 ticket（控制台和普通文件直连当前为 120 秒），并为该 IP 创建或续期默认 10 分钟的临时 grant。
4. 浏览器使用 ticket 直连 daemon。
5. daemon 校验 ticket 的来源 IP；盗取 ticket 的其他来源不能使用它。

临时 grant 的 TTL 只控制**新建连接**，默认 10 分钟，可在 60 到 3600 秒之间配置。系统链会放行 daemon 端口的 `ct state established,related` 流量，因此已经建立的上传、下载或 WebSocket 不会在传输数小时后因为 grant 到期而断开。连接异常重建时需要重新申请 ticket 和 grant。

退出登录时，Panel 最佳努力向所有在线 daemon 撤销该会话的未使用 ticket 与临时 grant；TTL 是可靠兜底。第一版不强制中断已经开始的大文件传输。

## 6. 系统访问保护

系统访问保护默认关闭。关闭时，Prism 业务白名单不会接管 daemon 端口，保留既有部署兼容性。

管理员显式开启后，daemon 端口仅允许：

- loopback；
- 配置的长期 Panel 控制来源 CIDR；
- 当前已认证控制 WebSocket 的来源（可在启用请求中自动保留）；
- 仍有效的浏览器临时 grant。

其他来源会被拒绝。开启请求必须至少包含一个长期控制来源或当前控制连接来源，否则 daemon 拒绝应用，避免远程锁死。系统保护的修改、关闭和控制来源删除均视为高风险操作。

Panel 位于反向代理后时，只有在代理来源被显式配置为可信后，才可使用 `X-Forwarded-For` 推导浏览器 IP；未配置可信代理时只使用 TCP 对端地址，绝不盲目信任请求头。

## 7. 控制协议

Panel 到 daemon 的管理 WebSocket 增加：

```text
firewall.status
firewall.list
firewall.rule.create
firewall.rule.update
firewall.rule.delete
firewall.system.configure
firewall.grants.revoke_session
```

`ticket.create` 增加可选的 `source_ip` 和 `session_id`。只有 Panel 明确请求直接浏览器访问时才设置这些字段。

状态至少返回：操作系统、后端、支持状态和原因、当前 revision、业务规则、系统访问设置、动态 grant 数量、实际表是否存在、期望/观测指纹、漂移状态和最近错误。

## 8. 前端与 API

Panel API 是 daemon 控制协议的权限边界：

- `firewall.view`：查看 Linux 节点状态、业务规则和只读系统访问摘要。
- `firewall.manage`：修改业务规则、系统访问设置和撤销临时授权。
- 所有写操作写入现有操作审计，记录节点、修订号、规则摘要和成功/失败原因。

网络白名单页按节点展示：

- 后端可用性、nftables 状态、revision、配置漂移和错误。
- 业务白名单列表及结构化创建/编辑表单。
- 只读系统访问状态和临时授权数量。
- Windows 或缺少 root/nftables 的 Linux 节点显示具体不可用原因，禁用写入操作。

节点详情页保留“网络白名单”标签，并跳转到当前节点的白名单视图。

## 9. 恢复、漂移与失败

- daemon 启动时读取本地状态和专用 nftables 表；已保存规则而表不存在时，daemon 重新应用本地快照。
- 表存在但与最近成功指纹不一致时标记 `DRIFT`，不自动覆盖管理员的同 boot 外部修改。
- 原子应用失败时不更新本地成功状态，调用方收到明确错误。
- 临时 grant 不持久化；daemon 重启后浏览器重新申请 ticket/grant。
- 业务规则的完整替换和临时 grant 更新使用同一 daemon 串行锁，避免并发破坏专用表。

## 10. 验证范围

单元测试至少覆盖端口/CIDR 规范化、重叠拒绝、daemon 端口保护、revision 冲突、ticket 来源绑定、grant TTL 复用和状态指纹。

Linux 集成验证至少覆盖：`nft --check`、原子应用失败不改变既有规则、IPv4/IPv6、系统访问保护、长传输的 established 连接、daemon 重启恢复和外部修改漂移。

# PrismPanel 基础框架运行说明

## 环境要求

- Go 1.21+
- Node.js 20+
- MySQL 8.0+

当前处于开发阶段，数据库只包含最终结构，不提供旧表或旧数据迁移。

## 目录

```text
daemon/                    节点守护进程
panel/                     面板后端
frontend/                  Vue 3 管理界面
docs/面板设计.md           产品与技术设计
```

面板负责登录、用户组、全局权限、审计和多节点连接。守护进程负责节点本地的进程、文件、控制台和部署执行。panel 与 daemon 是多对多关系。

## 初始化 MySQL

```sql
CREATE DATABASE prismpanel
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

数据库连接使用结构化 YAML 配置：

```yaml
database:
  url: 127.0.0.1:3306
  username: root
  password: replace-with-your-password
  name: prismpanel
  table_prefix: prism_
  max_open_conns: 10
  max_idle_conns: 5
```

`table_prefix` 只能包含字母、数字和下划线，并且必须以字母开头。首次运行 panel 会使用该前缀创建当前版本的数据表和四个内置用户组。

## 构建前端

```powershell
cd "frontend"
npm install
npm run build
```

生产构建输出到 `frontend/dist`，panel 默认直接托管该目录。

## 创建超级管理员

数据库中没有用户时，访问登录页并输入用户名和密码。第一组通过校验的凭据会原子创建首位超级管理员并立即登录。

用户名使用 3-32 位小写字母、数字、点、下划线或连字符，密码至少 6 个字符。用户创建后，登录页恢复为普通登录，不再提供初始化入口。

系统不提供公开注册入口，也不创建默认账号或默认密码。至少需要保留一个正常状态的超级管理员。

## 启动守护进程

```powershell
cd "daemon"
go run ./cmd/prism-daemon
```

首次启动会生成：

- `daemon/data/daemon.yaml`
- `daemon/data/secret.json`

查看节点令牌：

```powershell
go run ./cmd/prism-daemon -show-secret
```

重置令牌：

```powershell
go run ./cmd/prism-daemon -reset-secret
```

重置令牌不会改变稳定节点 ID，但所有使用旧令牌的面板都会认证失败。

## 启动面板

```powershell
cd "panel"
go run ./cmd/prism-panel
```

默认访问地址为 `http://127.0.0.1:8080`。首次运行会生成：

- `panel/data/panel.yaml`
- `panel/data/master.key`

`master.key` 用于加密节点长期令牌，丢失后已有节点令牌无法解密。

## 添加节点

登录后进入“节点”，填写：

- 节点名称
- 完整 HTTP 或 HTTPS 连接 URL
- daemon 节点令牌
- 可选公网 URL

连接测试是可选操作。面板允许先保存离线、不可达或令牌错误的节点，后台会持续重连并显示最近错误。

同一面板按规范化连接 URL 去重。协议和主机名不区分大小写，末尾斜杠和默认端口会被归一化。不同 URL 即使连接到同一个 daemon 也可以分别添加。

## 管理服务器

进入“服务器”后可以通过网格卡片跨节点查看、新增和筛选服务器组。当前支持固定实例和镜像服务器组。点击卡片进入详情后，默认显示控制台，并可选择服务器组内的一个子服：

- 当前子服启动、重启、关闭和强制关闭
- 服务器进程配置与单服控制台编码设置
- 带 ANSI 颜色的实时控制台输出
- 经过 `console.command` 权限检查的控制台命令输入
- 按子服组织的概述、玩家数据、插件数据和配置布局
- 可选择子服查看最近 10 分钟的 CPU、内存、玩家数和 TPS 折线图
- 镜像服务器组按目标子服部署，并在弹窗中查看进度和日志

实例 CPU 使用 Windows 任务管理器口径，表示该进程树占整台主机 CPU 总能力的比例，范围为 `0%` 到 `100%`。实例内存为进程树工作集总和。玩家、TPS 和插件列表在 PrismMC 上报后显示；插件未连接时对应字段显示无数据状态。

panel 后台每 5 秒从所有在线 daemon 读取一次指标，在内存中为每个节点和实例保留最近 10 分钟、最多 120 个采样点。panel 重启后历史重新累计。节点详情的性能页显示主机总 CPU、每个逻辑核心 CPU、主机内存和最近 10 分钟趋势。

总览和节点列表直接显示最新主机 CPU 与内存快照，全局在线玩家数和运行实例数也从最新实例指标汇总。前端内存统一换算为 GB 显示。

镜像部署使用独立的 `server.deploy` 权限，管理员和运维人员默认拥有该权限。部署任务开始时会锁定所有选中子服，生命周期、控制台命令、配置修改和删除操作在任务完成或取消前都会被拒绝。运行中的目标会先正常停止，并在安全部署完成后恢复运行。

单个子服的镜像文件通过有界工作池并发复制，默认并发数为 `4`，可通过 daemon 配置 `files.copy_concurrency` 调整，允许范围为 `1` 到 `64`。多个子服仍按顺序部署。部署弹窗同时显示子服完成进度、当前文件阶段、完成文件数和复制字节数。

## 文件管理

拥有 `file.read` 权限的用户可以在服务器详情的“文件”页浏览和下载文件。`file.write` 控制新建、上传、编辑、重命名和移动，`file.delete` 单独控制删除。镜像服务器组同时提供镜像源和各子服目录；镜像部署期间相关写操作会被锁定，浏览和下载仍然可用。

文件页使用类似 VS Code 的左右分栏：左侧是可懒加载展开的完整文件树，右侧显示和编辑当前文件。树节点支持选中、展开、悬浮操作和文件类型图标，刷新时保留展开状态；单目录超过 500 项时前端会继续读取后续游标。

新增服务器时可以选择一个 ZIP 初始化文件。固定实例会导入工作目录，镜像服务器组会导入镜像目录；服务器配置先创建，导入失败时服务器仍然保留，并可从空根目录的文件页重新导入。固定实例重试导入时必须处于已停止或异常状态。

文件内容由浏览器凭短期票据直连 daemon。daemon 未配置 `server.public_url`、浏览器无法直连或主动要求代理时，panel 使用流式代理；新建、移动、重命名和删除始终经过代理。编辑器支持 UTF-8、UTF-8 BOM 和 GBK，按文件扩展名动态加载 CodeMirror 语法高亮；`Ctrl+S`（macOS 为 `Cmd+S`）复用保存按钮流程，并使用内容 SHA-256 检测并发修改。

daemon 文件限制示例：

```yaml
files:
  max_edit_file_size: 5242880
  max_upload_file_size: 2147483648
  max_extracted_size: 21474836480
  max_concurrent_transfers: 4
  copy_concurrency: 4
```

普通上传先写入目标目录中的临时文件，接收完成并校验大小后再原子发布。ZIP 初始化仅支持空工作目录，拒绝越界路径、符号链接和非常规文件，并限制解压总大小；解压到同级临时目录后再通过目录重命名发布。目录删除必须在界面中明确确认递归删除；系统不提供节点系统盘浏览、chmod、通用压缩解压或 URL 下载。

## PrismMC 插件

daemon 启动任何受管进程时都会注入 `PRISM_DAEMON_WS`、`PRISM_INSTANCE_ID`、`PRISM_SESSION_ID` 和 `PRISM_PLUGIN_TOKEN`。普通 Python、Go 或其他进程会忽略这些变量，不影响进程管理。

PrismMC 插件读取这些变量后连接 daemon 的本机 `/api/v1/ws/plugin` WebSocket。插件令牌随机生成并绑定当前实例、启动代次和进程树，实例退出后立即失效，不复用节点管理令牌。

指标分工：

- daemon 每 5 秒采样实例进程树 CPU、工作集内存，以及主机总 CPU、逐逻辑核心 CPU 和主机内存。
- PrismMC 每 5 秒上报 TPS、MSPT、JVM 堆、线程、玩家和 Bukkit/Paper 插件列表。
- 插件每 10 秒发送心跳，断线后指数退避重连。

构建插件：

```powershell
cd "prism-plugin"
mvn package
```

输出为 `prism-plugin/target/PrismMC-0.1.0.jar`。复制到子服 `plugins` 目录后，需要通过 daemon 重新启动该子服，使其获得本次启动的临时凭据。

控制台编码支持 `UTF-8` 和 `GBK`。浏览器、panel 和 WebSocket 始终传输 UTF-8，daemon 在服务器进程边界流式转码；运行中修改编码后需要重启实例才能完整生效。

服务器查看、配置、删除、生命周期、控制台读取和命令输入分别使用对应权限节点。拥有 `console.read` 但没有 `console.command` 的用户只能查看输出。

## 前端开发服务

面板运行在 8080 端口时，可以单独启动 Vite：

```powershell
cd "frontend"
npm run dev
```

开发页面为 `http://127.0.0.1:5173`，`/api` 和 WebSocket 请求代理到 `http://127.0.0.1:8080`。
